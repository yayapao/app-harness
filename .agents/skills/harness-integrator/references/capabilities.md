# 业务能力与验收

## 审核发现结果

discovery.json 的 candidates 包括 TypeScript/JavaScript 导出函数及 JSON OpenAPI 操作。其他语言、类方法、包装后的工具、重导出和 YAML OpenAPI 仍需通过源码、接口契约和现有测试发现。报告不执行代码、不推断最终业务权限；permissionHint 仅是名称或 HTTP 方法的线索。

读取候选函数实现及其调用链，优先选择已有服务层或授权 API。不可仅根据 get、POST 等名字确定副作用。先查看参数、数据范围、返回值、角色权限和现有 UI 调用方式。React Client Component、未审核 shell/SQL 操作及任意地址 fetch 都不作为默认工具。

在目标项目 docs/harness-integration.md 中维护能力映射：

| 项目       | 记录                                         |
| ---------- | -------------------------------------------- |
| 源码证据   | 文件、符号或 operationId、关键调用链         |
| 参数契约   | Zod 或宿主校验、必填字段、边界、禁止额外字段 |
| 权限与范围 | read/write/destructive，用户和租户数据范围   |
| 确认与取消 | 写操作确认内容、AbortSignal 或宿主取消方式   |
| 注册       | Plugin/Skill、工具名、Agent 名、显式白名单   |
| 状态       | 已接入、排除及原因、缺少环境的具体阻碍       |

候选列表不作为模型工具列表。执行路径必须绑定到经过审核的业务函数，参数只提供业务值，不允许模型给出模块路径、函数名、任意 SQL 或可执行命令。

## 基础 Agent 与流程

HarnessAgent 是可执行接口，不只是 systemPrompt：execute 接收 input 和 ToolContext，必须返回业务结果。将经过鉴权、只读的业务服务注入 Agent；参数独立校验，传递 context.abortSignal，在关键步骤输出 agent_progress。

一个常见的最小流程是“查找业务对象 → 校验归属 → 读取相关记录 → 汇总状态和异常”。具体字段和操作由项目证据决定。流程可以放在业务服务层，再由 Agent.execute 调用；不必引入第二套流程引擎。结果包含可核查的记录 ID、状态或统计，空数据明确返回空结果。

执行框架要保持这些规则：

1. 只读 Agent 只组合已校验的只读服务，不得通过内部函数或 HTTP 调用产生写入。
2. 需要写入的流程先生成操作建议，再用独立 write/destructive 工具提交；每个写入步骤经 Gateway 的权限与人工确认。不要直接调用 writeTool.handler 绕过 Gateway。
3. 若一个已审核的原子业务操作包在 write Agent 内，Agent 权限必须为 write，确认参数能说明实际影响范围；内部业务授权仍须执行。
4. 失败立即结束该运行，取消向下传递；不能返回“完成”掩盖部分失败。涉及多次写入时复用宿主事务或补偿机制。
5. 同步注册 Plugin、Skill、Agent 与 allowedTools/Policy。Registry 中 Agent 会映射为 callable tool；白名单也要包含 Agent 名。

没有现成业务服务时，可按用户明确目标开发必要的最小服务。缺少目标且无法从项目推断真实业务时，先完成宿主与 UI，再提出具体缺项；不以时间/便签或返回固定文案的 Agent 冒充业务能力。

## 保存与验证

目标默认至少有一个真实只读业务工具、一个真实基础 Agent、一个可执行流程，流程可作为该 Agent 的执行体。管理页必须从 Registry 显示对应 Skill、Agent 与工具，保存参数影响下一次模型或流程运行。

测试用受控业务依赖验证编排逻辑，同时沿现有测试框架验证实际服务包装、授权拒绝和注册结果。真实模型检查只在配置可用且用户授权的范围内进行，不能把模拟模型结果描述成真实模型验收。

| 层面         | 观察结果                                                     |
| ------------ | ------------------------------------------------------------ |
| 工具         | 参数无效被拒绝；正常输入命中真实服务；不同用户的数据范围隔离 |
| Agent / 流程 | 实际执行步骤与返回证据对应；失败和取消传播；读 Agent 无写入  |
| 权限         | 未授权工具和 Agent 不对模型暴露，也不能直接执行              |
| 确认         | 未确认、取消或过期确认不执行写操作                           |
| 运行参数     | 保存后的模型、轮数、输出上限出现在下一次实际配置读取中       |
| 注册关系     | 能力列表来自当前 Registry，与工具/Agent 的名称和权限一致     |
| UI           | 全局入口可达；弹窗开关、焦点、消息流、确认和管理导航正常     |
| 再次接入     | 已有业务代码、插件、设置与登录不被重置，清单可增量更新       |

如果环境禁止启动服务，只报告静态与运行时测试，浏览器验收留为明确未验证项。交付时保留实际启动命令及环境配置说明。
